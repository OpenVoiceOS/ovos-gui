## 2. Release-blocking bugs in ovos-gui #100 (with evidence)

- **B1 (CRITICAL):** `service.py:59` gates on `hasattr(OVOSGuiFactory, 'create_all')`,
  but the published factory has only `create`/`get_class`. → `adapters=[]` →
  `service.py:64` raises `RuntimeError("No GUI adapters found")`. **GUI service is
  dead on any released install.** Root cause of the 3 failing tests.
- **B2 (CRITICAL/release-blocker):** `pyproject.toml:15-16` pin
  `ovos-plugin-manager` and `ovos-legacy-mycroft-gui-plugin` to
  `file:///home/miro/PycharmProjects/...` absolute paths → uninstallable elsewhere,
  no PyPI release possible. CI is green only because it installs these local paths,
  **masking B1**. Do not trust remote CI here.
- **B3 (HIGH):** `namespace.py` defines `_safe_call`, `forward_to_gui`,
  `handle_clear_namespace`, `handle_delete_all_pages/page`, `_remove_pages`,
  `_parse_persistence` **twice** (~359-481 dead, ~532-659 live). Dead `forward_to_gui`
  calls adapters with wrong arity — a merge accident.
- **B4 (HIGH):** live `handle_delete_all_pages`/`_remove_pages` reference
  `namespace.pages` / `namespace.remove_pages()` which **no longer exist** on the
  template-only `Namespace` → `AttributeError` on any `gui.page.delete*`. Untested.
- **B5 (HIGH):** **contract self-contradiction.** `CONTRACT.md`/`GUI_DESIGN.md` spec a
  single `routing_key` (2-arg hooks); the live code passes **both `session_id` and
  `site_id`** (`on_namespace_activated(name, session_id, site_id)`, etc.). Adapters
  written to the published contract break (or hit the silent `_safe_call` fallback).
- **B6 (MED):** `_get_session_key` (496-504) implements only 2 of the 3 routing
  cases — the explicit `session_id=="default"→"default"` priority is missing.
- **B7/B8 (MED):** `_emit_namespace_displayed_event` and timer removal put the
  session *key* into a `site_id` field and lose routing identity on timed removal.
- **B9 (LOW):** `_safe_call` catches `TypeError` and retries with fewer args,
  silently hiding B5 and any real adapter signature bug.
- **Tests:** 3 failed / 110 passed locally. end2end uses `Mock()` adapters (accept
  any arity) → B5 invisible; routing tested only with `"default"` → B6 untested;
  delete-page path untested → B4 invisible; real factory loading untested → B1 by design.

## 3. The headline qt5 #5 risk: protocol drift

- **Template layer: conformant** — all 21 `SYSTEM_*` templates present (superset).
- **Transport layer: DRIFT (the #1 risk).** qt5 offers `wss` (`MYCROFT_GUI_TLS=1`)
  and sends `?token=`; the **only existing adapter** (`ovos-legacy-mycroft-gui-plugin`)
  speaks **plain `ws` only and never validates a token**. Setting TLS → connection
  fails; token → false security. Also: qt5 unilaterally **removed the port-negotiation
  handshake** the server still implements.
  → TLS/token must land in the legacy adapter **first**, or ship the client feature
  explicitly labelled experimental/no-op.
- No CI; `-Werror` global with 18k lines of AI C++ (brittle); committed `build/`
  artifact; hand-maintained version + duplicate `PROJECT()`; 9 root scratch docs
  (violate no-meta-commentary rule). ovos-shell absorption is byte-complete, but the
  Wayland/KWin compositor + systemd session + `.desktop` units live in the OS image
  and still need repointing to `ovos-gui-app --shell`.
- **Qt6 is NOT in #5.** qt6 is a genuinely separate client (uncommitted local rework),
  speaking the legacy `mycroft.session.*` protocol — needs human C++ review.

## 4. Cross-repo gaps blocking the chain

- **api-client:** complete code, but **no pyproject, no tests, no CI**, branch has no
  upstream. Bottom of the chain — everything waits on publishing it.
- **OPM #377:** draft; declares `opm.gui_adapter` **only in a docstring** — no
  `PluginType`/loader registered in `utils/__init__.py`, so adapters can't be
  discovered. Adds `AbstractGUIPlugin` alongside (not replacing) legacy `GUIExtension`.
- **workshop:** `OVOSSkill.gui` still imports `ovos_bus_client.apis.gui.GUIInterface`
  (`skills/ovos.py:34`, `app.py:6`) — nothing references `ovos_gui_api_client`. Needs
  a new rebind PR.
- **pyhtmx:** package named `ovos-pyhtmx-gui-client` (expected `ovos-gui-plugin-pyhtmx`);
  **no `opm.gui_adapter` entry point, no `PyHTMXGUIPlugin(AbstractGUIPlugin)` class**;
  test stub is empty.
- **ovos-gui:** local line is 12+ commits **behind** real `origin/dev` (missing #105
  bus-client-2.x, #106, #108, #110); bus-client cap inconsistent (`<2.0.0` in
  pyproject vs requirements.txt).

## 5. Version-cap risks
- Align **all** repos to `ovos-bus-client>=1.x,<3.0.0` (api-client declares none;
  ovos-gui still caps `<2.0.0` while upstream already allows 2.x — see
  `[[hivemind-busclient-2x-migration]]`).
- Adapters require `ovos-plugin-manager>=<release carrying #377+loader>`, cap
  `<3.0.0` (`[[opm-entrypoint-min-pm-version]]`). Floor doesn't exist yet.
- Steps 1→2→3→4 are **strictly serial through PyPI alphas** — landing out of order
  reds everything downstream.

## 6. Ordered landing sequence (the split plan)

Each step = rebase on real `origin/dev`, fix, local tests green, **draft PR (user
merges)**, then publish an alpha before the dependent step.

**Step 0 — Safety push** (all repos): commit WIP + push local branches to remote
feature branches. Precondition for everything.

**Step 1 — ovos-gui-api-client (publish first).** Add `pyproject.toml`
(name `ovos-gui-api-client`), real `test/` suite + gh-automations CI; declare
`ovos-bus-client>=1,<3`; PR→dev; release alpha. *Gate: nothing can pin it until published.*

**Step 2 — ovos-plugin-manager #377.** Un-draft; **register `opm.gui_adapter` as a
real `PluginType`/loader** (not just docstring); decide legacy `GUIExtension`
deprecation; PR→dev; release alpha (sets the adapter min-version floor).

**Step 3 — ovos-workshop rebind.** Swap `skills/ovos.py:34` + `app.py:6` to
`from ovos_gui_api_client import GUIInterface`; add `ovos-gui-api-client>=<step1>`;
keep legacy path intact; PR→dev; release alpha. *Requires step 1 published.*

**Step 4 — ovos-gui #100, decomposed** (requires steps 1–2 published):
- **4a Packaging/deps (BLOCKER):** replace `file://` pins (B2) with version specs;
  rebase onto real `origin/dev`; reconcile bus-client cap; land setup.py→pyproject + uv.lock.
- **4b CI/workflow** migration (the workflow deletions, gh-automations wiring).
- **4c Adapter factory loading:** fix B1 (require the real published factory API; no
  fallback-to-empty); `opm.gui_adapter` loading in `service.py`.
- **4d Dispatch + routing:** SYSTEM_* detection + `_dispatch_template_to_adapters` +
  `_gui_routing_key`; fix B3 (drop dead duplicate block), B6 (add default case), B7/B8.
- **4e Contract reconciliation (one source of truth):** pick single `routing_key`
  (CONTRACT.md) vs `(session_id, site_id)` (code) and make code + CONTRACT.md +
  GUI_DESIGN.md agree; drop silent arity fallback (B5/B9); resolve dead page model /
  B4 per TECH-001; trim contradictory docs.
- **4f Real-adapter tests:** replace `Mock()` with a spec-conformant test adapter
  (enforces arity); cover delete-page, site_id + UUID routing, real factory loading.

**Step 5 — Adapters:**
- **Legacy** (`ovos-legacy-mycroft-gui-plugin`): subclass `AbstractGUIPlugin`,
  register `opm.gui_adapter`, require OPM≥step2. Add `wss`+token if qt5 TLS is kept.
- **pyhtmx**: rename package → `ovos-gui-plugin-pyhtmx`; add `opm.gui_adapter` entry
  point + `PyHTMXGUIPlugin(AbstractGUIPlugin)`; real tests; fix `main` tracking; then
  refresh ovos-gui #73 on top.

**Step 6 — Clients (qt5/qt6/pyhtmx UI):**
- qt5 #5 split: (1) CMake/Qt5/C++17 modernization + hygiene (drop committed `build/`,
  scratch docs); (2) `mycroft→ovos` rename (atomic); (3) WS protocol cleanup *without*
  TLS; (4) TLS/token **gated** on legacy-adapter support; (5) template set; (6)
  session_id/site_id multi-screen; (7) `--shell` absorption (+ OS-image session/desktop
  repoint); (8) notifications/widgets; (9) autotests + C++/CMake CI.
- qt6: secure uncommitted rework, then **human C++ review** before packaging; align
  protocol enum with qt5/legacy.
- Stale qt5 remote branches (`dont-send-messages...`, `no-launching-mycroft`,
  `simplify-core-bus-messages`) → supersede/drop (pre-rework, some never compiled).
